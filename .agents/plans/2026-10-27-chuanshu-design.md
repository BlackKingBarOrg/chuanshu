# 传书（Chuanshu）设计方案

## Goal

为 Omarchy 小团队做一个纯局域网的飞鸽式工具：无服务器、无账号、无云端，开机即可发现同事、聊天、高速传文件。第一版只服务几个人，不做组织管理。

## Success Criteria

- 两台同局域网机器装好后零配置互相可见，不用输 IP、不用注册。
- 一对一聊天和全员广播可用；对方不在线时发送立即明确失败，不排队、不假装送达。
- 文件、文件夹、图片附件可发送；大文件有进度和速度，中断后手动重发可续传，完成有完整性校验。
- 聊天中的附件按回车用操作系统默认程序打开，不做终端内预览。
- 私聊内容加密；冒充者改昵称无法冒充已核对过的同事。
- 聊天记录保存在本机，可查历史。
- 一条命令安装，后台服务开机自启。

## Approach

### 语言选型：Go

选 Go，不选 Rust。

- Go 的并发模型天然适合同时维护多个同事连接加多个文件传输，写起来直接。
- Go 编译出单个静态二进制，同事机器上拷贝过去就能跑，安装和升级成本最低。
- TUI 用 Bubble Tea，是 Go 生态成熟的终端界面框架；加密用 flynn/noise，是 Noise 协议的 Go 实现；局域网发现用 hashicorp/mdns。关键件都有现成实现，不用造轮子。
- Rust 的优势是 Ratatui 界面库更精致、内存安全更硬。但对几人小团队的第一版，它的开发和异步状态管理成本明显更高，而聊天传文件是网络和磁盘瓶颈，不是 CPU 瓶颈，Rust 的性能优势用不上。

重估条件：若将来要长期解析不可信来源的复杂二进制协议、或团队主力变成 Rust，再讨论迁移。

### 总体架构：单二进制，进程分离

一个二进制、三种运行模式：

- 后台守护进程：负责发现同事、维护连接、收发消息、传输文件、发桌面通知。关掉终端窗口照样能收文件。
- TUI 前台：只负责界面，通过本机进程间通道和守护进程通信。
- CLI 子命令：脚本和启动器可直接调用，例如选人发文件，不必先开界面。

守护进程由用户级系统服务托管，开机自启、崩溃自拉。

### 发现与身份（借鉴 bitchat）

- 发现走双通道：mDNS 为主，UDP 广播兜底。任一通道发现即可见，适应不同路由器设置。
- 每台机器首次运行生成一对长期密钥，机器身份就是密钥指纹，不依赖昵称。
- 在线公告带签名：昵称可以随便改，签名冒充不了。
- 第一次和某位同事通信时，双方核对一串短验证码并钉住对方公钥；之后自动完成，不再打扰。
- 同事列表只显示最近一分钟内有公告的人；超时自动变离线。

### 协议与传输

- 传输层和业务层分离：上层只管聊天和文件，下层负责建连和选路。将来跨网段要加中继时只改下层。
- 私聊连接建立时完成加密握手（Noise XX 模式，双方互验身份、自带前向保密），之后的文字、回执、文件分片全走这条加密连接。
- 每条消息有全局唯一编号，接收方按编号去重；回执分两级：对方守护进程收到、对方在界面里看过。
- 广播频道在小团队下实现为对所有在线成员逐个单发，不做组播。

### 聊天与离线规则

- 对方不在在线列表、或连接建立失败，发送立即失败并在界面标红，提示对方不在线。
- 不做离线队列、不做存储转发、不做托人带话。这是已确认的取舍，换来第一版大幅简化。
- 文件传输中途断线不算彻底失败：接收方保留未完成文件，下次重新发送同一文件时从断点续传。

### 文件与附件

发送端：

- 在 TUI 里用附件命令选路径，支持路径补全。
- 从文件管理器把文件拖进终端，自动识别粘贴进来的路径为附件。
- 复制图片后在输入框粘贴，程序从系统剪贴板取出图片作为附件（与编程 agent 在终端里贴图的做法一致）。
- 文件夹按清单逐项发送，保持相对路径；符号链接默认跳过并告知。

接收端：

- 任何文件落盘前，先在界面和桌面通知里弹确认，同事也不能直接往你磁盘塞东西。
- 接收先写临时未完成文件，全部收完校验通过后才改名为正式文件，杜绝半截文件冒充成品。
- 文件名做安全清洗，禁止路径穿越写到下载目录之外；同名文件自动改名不覆盖。
- 默认存入下载目录下本工具专属子目录。

聊天里的附件只显示一行（图标、文件名、大小）。回车用操作系统默认程序打开：图片进看图程序，文档进对应软件。不做终端内渲染预览。

### TUI 布局

```
┌─同事──────┬─ 与 张三 的对话 ────────────────┐
│ ● 张三     │ 张三 10:02 在吗                  │
│ ● 李四     │ 我   10:03 在，文件发你          │
│ ○ 王五 离线│ 我   10:03 [文件 报告.pdf 2.3MB] │
│ # 全员广播 │ 张三 10:04 收到了                │
├───────────┴────────────────────────────────┤
│ 输入消息，/file 加附件，Enter 发送          │
│ 张三 在线 · 已加密 · 传送中 45% ━━━━░░░░    │
└────────────────────────────────────────────┘
```

- 左栏同事列表，在线在上、离线置灰；未读数标在名字后。
- 右栏消息流，附件为单独一行，回车打开，另有按键另存和查看传输详情。
- 底栏输入，支持粘贴图片、拖入文件路径、斜杠命令（切人、加附件、改状态、退出）。
- 全键盘操作：切会话、切同事、确认收文件都不碰鼠标。

### 本地存储与系统集成

- 密钥、聊天记录、未完成传输都存本机用户目录下，密钥文件权限仅本人可读。
- 配置用单个文本配置文件：昵称、下载目录、端口可改。
- 收到消息和文件请求时发桌面通知；顶栏未读提醒、跟随 Omarchy 主题配色放第二阶段。
- 安装做成系统包加一条命令，自动装好自启服务，并提示需放行的局域网端口。

## Steps

1. 骨架：单二进制三模式跑通，守护进程可自启，TUI 能连上守护进程显示空界面。完成标志：开机后进程在，打开 TUI 不报错。
2. 发现与身份：双通道发现、签名公告、密钥生成与钉住、短码核对界面。完成标志：两机零配置互相可见，改昵称不影响身份识别。
3. 聊天：加密建连、一对一文字、两级回执、离线立即失败、广播频道、本地历史。完成标志：两机对话加密可验，对方关机发送立即报错。
4. 文件：附件三入口（命令选、拖入、粘贴图片）、接收确认、分片传输、进度速度、断点续传、整文件校验、回车系统打开。完成标志：1GB 文件传完校验一致，中途断网重发能续上。
5. 打磨与交付：桌面通知、安装包、自启与端口提示、双机实测清单过一遍。完成标志：新机器一条命令装好能收发。

## Validation Plan

- 每步完成后跑单元测试和静态检查，协议编解码、文件名清洗、断点偏移计算必须有针对性用例。
- 身份与加密用例：公钥被替换时必须报警；抓包只能看到密文。
- 双机黑盒实测（真实两台机器，不用模拟代替）：首次发现、短码核对、聊天、离线失败、广播、图片粘贴发送、大文件、断网续传、回车打开附件，逐项过。
- 失败路径实测：对方传一半关机、磁盘同名文件、非法文件名、拒绝接收，都要有明确提示且不留半截成品文件。

## Risks / Open Questions

- 办公室网络若开了客户端隔离或分了网段，双通道发现也会互相看不见。第一版假设同一平坦局域网；实测不通再评估加中继，那会改变纯局域网前提，需另行拍板。
- 防火墙未放行端口会出现看得见人、连不上线。安装环节必须把端口放行做成自动或明确提示。
- 不同终端对粘贴图片、拖入路径的支持不一致。第一版以剪贴板取图为正式路径，拖入路径为增强，实测哪种终端不行就在文档注明。
- 开放问题：无。端口号、下载目录、短码形式均为可逆默认值，实现时定死并写进配置，不阻塞本方案。
